# AGENTS.md

Instructions for AI coding agents (and humans) working in **OWL Akrida**, a load-testing tool for
DIDComm deployments (ACA-Py, Credo). Locust drives many simulated *holder* agents, each a Node.js
Credo subprocess, against a mediator, issuer and/or verifier.

`CLAUDE.md` imports this file. Edit this file, not `CLAUDE.md`.

## Boundaries (read first)

- **Never run load against a system you lack written permission to test.** Do not add default URLs
  that point at real third-party systems, and do not launch Locust or Docker runs against remote
  hosts unless the user names the target and confirms they are authorized.
- **No secrets in git.** `.env` is ignored; only `sample*.env` is committed, with placeholders
  (`<your-issuer-token>`). Never commit bearer tokens, API keys, wallet keys, or real
  `ISSUER_HEADERS` / `VERIFIER_HEADERS` / `HOLDER_HEADERS` values, and never print them in logs, test
  output, plans or reviews.
- **No real PII or credential data** in tests, fixtures, docs or `ai/` records. Use synthetic values
  like the `score=test` default.
- Ask before: pushing, force-pushing, opening PRs, deleting branches/files you did not create,
  changing CI workflows, or bumping dependency or Docker base versions.
- Do not edit `pdm.lock` or `load-agent/yarn.lock` by hand. Change `pyproject.toml` /
  `package.json` and regenerate with `pdm lock` / `yarn install`.
- Do not edit `CHANGELOG.md` by hand; it is generated by the `release:*` scripts.

## Architecture

```
Locust (Python, gevent)
  └─ locust-files/*.py          scenarios (one TaskSet/User per test type)
       └─ locustClient.py       CustomClient: picks issuer/verifier/holder impl from settings
            ├─ agents/issuer/   BaseIssuer  -> acapy.py, acapy_v2.py   (HTTP to ACA-Py admin API)
            ├─ agents/verifier/ BaseVerifier-> acapy.py, acapy_v2.py   (HTTP to ACA-Py admin API)
            └─ agents/holder/   BaseHolder  -> credo.py
                 └─ spawns `node dist/agent.js` per user; talks JSON over stdin/stdout
                      └─ agent.ts (Credo 0.5.x agent: connections, mediation, credentials, proofs)
```

Key facts:

- **Holder = Node subprocess.** `agents/holder/credo.py` starts `node dist/agent.js`, sends one JSON
  command per line on stdin (`{"cmd": "start" | "receiveInvitation" | "receiveCredential" |
  "presentationExchange" | "ping_mediator" | "shutdown" | ...}`) and reads exactly **one JSON line**
  back on stdout. Design rule from `DEVREADME.md`: *one command, one response, via stdout*. Anything
  else printed to stdout corrupts the protocol; log to **stderr**.
- **Adding a command** means changing both sides: the `cmd` dispatch in `load-agent/agent.ts`
  (~line 600+) and the matching method in `agents/holder/credo.py` (and `BaseHolder` if it is part of
  the interface).
- **Issuer/verifier/holder implementations are pluggable.** Implement the abstract base class in
  `agents/<role>/base.py`, then register it in the loader dicts in `locustClient.py`
  (`_load_issuer` / `_load_verifier` / `_load_holder`). Selection is by `ISSUER_TYPE`,
  `VERIFIER_TYPE`, `HOLDER_TYPE`.
- **Configuration** is environment-driven via `load-agent/settings.py` (`Settings`). New env vars must
  be added to `Settings`, `sample.env` (and `sample.demo.env` / `sample.vdr.env` if relevant), and the
  `environment:` list in `docker-compose.yml` or they will silently not reach the container.
- **Ports**: `portmanager.py` hands each agent a port from `START_PORT`–`END_PORT`; always return
  ports on shutdown/restart.
- **TypeScript is compiled** (`yarn tsc` -> `load-agent/dist/`). Python runs the compiled JS, so a
  stale `dist/` means stale behavior.
- Ledger genesis files live in `load-agent/networks/`. `instance-configs/` holds ACA-Py, mediator and
  database compose configs for standing up the system under test.

## Commands

Python 3.10+ with **pdm**; Node 20 with **Yarn 4 via Corepack** (`corepack enable`). Run from
`load-agent/` unless noted. These mirror `.github/workflows/ci.yml`, so make them pass locally before
pushing.

```bash
pdm install --dev                 # Python deps (pyproject.toml / pdm.lock are in the repo root)
pdm run pytest tests/unit -v      # unit tests (CI)
ruff check                        # lint (CI)
ruff format --check               # format check (CI); `ruff format` to fix
yarn install --frozen-lockfile    # JS deps
npx tsc --noEmit                  # TS type check (CI)
yarn tsc                          # build dist/ for running
```

Integration tests need Docker, `docker login ghcr.io` and the Indicio TestNet:
`pdm run pytest tests/integration -v --use-docker --use-real-ledger -m integration`. Do not run them
without the user asking.

Running the tool: see `docs/QUICKSTART.md`. In short, copy `sample.env` to `.env`, fill it in, then
`docker compose up` (UI on :8089).

Ruff config (`pyproject.toml`): line length 120, rules `E F W I N UP B`, target py310.

## Conventions

- **Python**: snake_case parameters (the legacy camelCase names were deliberately renamed; don't
  reintroduce them). Locust scenario files keep their camelCase file names (`N999` is ignored there).
  Use `raise ... from e`. Match the `abstractmethod` + docstring style in `agents/holder/base.py`.
- **TypeScript**: follow the existing style in `agent.ts` (no semicolons, single quotes).
- **Metrics**: scenario steps are wrapped with the `stopwatch` decorator in `locustClient.py`, which
  reports to Locust via `events.request.fire`. New steps should report the same way so they show up
  in results.
- **Tests**: new issuer/verifier/holder behavior gets unit tests in `load-agent/tests/unit/` using
  `pytest-mock`; mock HTTP and subprocess, never hit the network. Settings are read at import time,
  so patch with `monkeypatch.setattr(Settings, ...)` rather than env vars after import.
- **Docs**: if behavior or env vars change, update the relevant file in `docs/` and the sample env.

## Change management (SOC 2)

- Work on a branch; changes reach `main` only through a pull request with passing CI
  (python-tests, typescript-check, lint). Never push directly to `main`.
- Commits and PR titles follow **Conventional Commits** (`fix:`, `feat:`, `chore!:` for breaking).
  Keep breaking changes in their own PR.
- Sign off every commit (DCO): `git commit -s`.
- PR descriptions summarize all changes and call out security-relevant ones (auth, secrets, network
  targets, dependencies).
- Dependency changes: pin versions, keep lockfiles committed, and mention license/security impact.
  Do not add dependencies without a reason stated in the PR.
- Do not weaken or skip CI checks (`--no-verify`, disabling lint rules, `# noqa`) to get green; fix the
  cause or explain why in the PR.
- Log enough to audit a test run (target, scenario, user count) but never credentials or payloads that
  contain credential attribute values.

## AI plans and reviews (`ai/`)

- `ai/plans/{future,current,completed,abandoned}/` hold plan documents named
  `yyyymmdd-short-name.md`. For any non-trivial change, write or update a plan there first. Move it
  with `git mv` as status changes. See [ai/plans/README.md](ai/plans/README.md).
- `ai/review/` holds point-in-time review records, one folder per review, pinned to a commit SHA and
  not edited afterwards. See [ai/review/README.md](ai/review/README.md).
- Neither folder may contain secrets, licence strings, or real credential/PII data.

## Working style

- Prefer small, focused changes that match surrounding code; don't refactor unrelated files.
- Verify with the commands above before claiming something works. If you could not run something
  (Docker, ledger access), say so.
